## 2. 快速启动（三种方式）

### 2.1 方式一：一键启动（推荐）

**Windows（PowerShell）**：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File start.ps1
```

**Linux / macOS（Bash）**：

```bash
bash start.sh
```

启动脚本会自动：
1. 检查 Docker 容器状态，未运行时启动
2. 安装 Python 依赖（如需要）
3. 安装前端依赖（如需要）
4. 初始化存储并同步数据
5. 编译并启动 Java 后端（:8081）
6. 启动 Python API（:8080）
7. 启动 TalentMatch 前端（:3000）

按 `Ctrl+C` 停止所有应用层进程。数据库容器保持运行。

### 2.2 方式二：分步启动

**步骤 1：启动基础设施**

```powershell
docker compose up -d
```

**步骤 2：初始化存储（首次或数据更新后）**

```powershell
pip install -r requirements.txt
powershell -ExecutionPolicy Bypass -File scripts/init-storage.ps1
```

**步骤 3：启动后端服务**

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start-backend.ps1
```

**步骤 4：启动前端**

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start-talentmatch.ps1
```

### 2.3 方式三：手动启动

```powershell
# 1. Docker 容器
docker compose up -d

# 2. Python API（终端1）
pip install -r requirements.txt
python scripts/bootstrap_storage.py --sync
uvicorn app.main:app --host 0.0.0.0 --port 8080

# 3. Java 分析服务（终端2）
javac -encoding UTF-8 -d out backend/src/com/xh202621/*.java
java -cp out com.xh202621.App

# 4. TalentMatch 前端（终端3）
cd talentmatch
npm.cmd install
npm.cmd run dev
```

> 这些账号仅用于本地开发和比赛演示，不要直接用于公网服务器。

### 4.2 常用容器命令

```bash
docker compose up -d          # 启动全部基础设施
docker compose ps              # 查看容器状态
docker compose logs mysql      # 查看 MySQL 日志
docker compose down            # 停止并删除容器（保留数据卷）
docker compose down -v         # 停止并删除容器+数据卷（完全重置）
```

> ⚠️ **警告：`down -v` 不可逆，会永久删除所有命名数据卷（MySQL、Neo4j、ES、Milvus 数据）。**
> 不建议在存有正式数据的环境中执行此命令，仅适用于干净环境重置或一次性测试环境。

## 5. 数据初始化

### 5.1 增量同步（日常使用）

```powershell
python scripts/bootstrap_storage.py --sync
python scripts/sync_mysql_to_es.py --auto
```

增量同步使用 SHA-256 检测快照变化，只更新变更的表/文档。

### 5.2 完全重建（首次安装或重大变更后）

```powershell
python scripts/bootstrap_storage.py --reset
python scripts/sync_mysql_to_es.py --recreate-indices
```

### 5.3 Cleanroom 验证（推荐首次安装后执行）

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/verify-cleanroom.ps1
```

该脚本使用随机端口、独立 Compose 项目和全新卷，验证从零开始的完整安装链路。

## 6. 一键架构流水线

按架构重新生成 ETL、知识图谱、仓库导入文件、DeepSeek 抽取和简历解析产物：

```powershell
python scripts/build_full_pipeline.py
```

该命令依次执行：
1. `scripts/etl_unify_jobs.py` — ETL 统一 Schema
2. `scripts/build_knowledge_graph.py` — 知识图谱构建
3. `scripts/export_architecture_artifacts.py` — 仓库导入产物导出
4. `scripts/deepseek_extract.py` — DeepSeek 实体抽取（无 Key 时 dry-run）
5. `scripts/parse_resume_local.py` — 本地简历解析

```powershell
$env:DEEPSEEK_API_KEY='你的 DeepSeek API Key'
$env:DEEPSEEK_BASE_URL='https://api.deepseek.com'
$env:DEEPSEEK_MODEL='deepseek-chat'
```

```powershell

$env:MATCH_AI_API_KEY='你的 API Key'
$env:MATCH_AI_BASE_URL='https://api.deepseek.com'
$env:MATCH_AI_MODEL='deepseek-chat'
```

也可以在 TalentMatch 前端设置页面（http://localhost:3000）中配置。

生产环境应覆盖默认密码：

```text

NEO4J_URI=bolt://localhost:7687
NEO4J_USERNAME=neo4j
NEO4J_PASSWORD=<新密码>
NEO4J_DATABASE=neo4j
ES_HOST=http://localhost:9200
```

## 10. 常见问题排查

### 10.1 Docker 容器未启动

```powershell
docker compose up -d
# 等待所有容��健康检查通过
docker compose ps
```

### 10.2 端口冲突

```powershell
# 检查端口占用
netstat -ano | findstr "8080"
netstat -ano | findstr "8081"
netstat -ano | findstr "3000"

# 停止旧进程
powershell -ExecutionPolicy Bypass -File scripts/stop-dev.ps1
```

### 10.3 数据库连接失败

```bash
# 检查健康检查返回的具体状态
curl http://localhost:8080/api/health
# 如果 mysql 显示 "disconnected"，检查：
# 1. docker compose ps 确认容器运行
# 2. 确认密码和端口正确
# 3. 查看 MySQL 日志：docker compose logs mysql
```

### 10.4 API 返回 503

HTTP 503 表示对应数据库不可用。系统不会静默回退到 CSV。检查：
1. Docker 容器是否全部 healthy
2. 是否执行过 `bootstrap_storage.py --sync`
3. API 的环境变量是否指向正确的数据库地址

### 10.5 前端页面空白

```powershell
cd talentmatch
npm.cmd run build
# 检查 dist/ 目录是否有构建产物
# 如果构建失败，检查 Node.js 版本 ≥ 22.13
```

### 10.6 Java 编译错误

```powershell
# 确认 JDK 版本
javac -version
# 需要 JDK 21+

# 确认源文件路径
dir backend\src\com\xh202621\*.java
# 应包含 5 个 .java 文件
```
