### 段落2：技术架构与数据规模（1:30）

**[画面：分层架构图，从下往上展示]**

**旁白**：

"先看整体架构。系统分为四层。

最底层是 Docker Compose 管理的四个数据库——MySQL 做结构化存储、Elasticsearch 做全文检索、Neo4j 做图谱查询、Milvus 做向量检索。

中间是双后端服务层——FastAPI 提供公开 API，67 条路由，自带 Swagger 文档；Java 分析服务负责图谱构建、演化聚合和人岗匹配引擎。

最上层是 React 19 加 TypeScript 加 Vite 的 TalentMatch 前端，统一展示仪表盘、图谱可视化、匹配诊断和演化趋势。

现在我们来看数据规模。"

**[画面：关键数字大字展示，逐个弹出]**

**旁白**：

"从六个活跃采集来源——腾讯、美团、华为、百度招聘，以及国家大学生就业服务和公共就业平台——我们累计采集并 ETL 统一处理了五万五千两百六十七条岗位记录。

从这些 JD 中，系统抽取了六万九千六百一十五条技能证据，构建了包含九百零七个节点和一千八百零六条边的岗位能力知识图谱。

另外，三万四千零九十四行岗位别名消歧数据，将同一岗位的多种写法映射到规范 ID——比如 'JAVA后台开发'、'Java服务端研发'、'高级Java工程师' 都被统一为 'Java 后端工程师'。"

### 段落3：数据治理与质量控制（1:00）

**[画面：ETL 统一 Schema 示意图 → 质量评分表]**

**旁白**：

"数据治理是我们最重视的基础能力。

每条岗位记录进入系统时，需要经过三十多个字段的统一 Schema 标准化，包括八个追溯字段——来源 ID、来源 URL、采集时间、发布时间、内容哈希——保证全链路可审计。

质量评分采用扣分制，满分一百，十二项缺陷逐项扣分。缺失岗位名扣二十五分，重复内容扣二十分，未命中技能扣十分。

评分结果分为 A、B、C、D 四级，其中 C 级和 D 级记录不会进入核心指标口径。更重要的是，质量评分不是孤立的——它联动影响下游应用：无技能命中的记录不生成图谱边，重复内容只保留一份用于趋势统计，低质量岗位降低匹配推荐的可信度。"

通过岗位别名消歧和技能聚类，系统将这个候选新岗位统一命名为 'AI 智能体工程师'。

大家可以看到系统生成的结构化岗位定义——"

**[画面：展示新岗位定义卡片]**

**旁白**：

"五项核心职责，包括设计和开发基于大语言模型的智能体应用系统、实现 Agentic Workflow、集成 LLM API 等。

五项必备技能——Python 加 LangChain 等 Agent 框架、大语言模型基础、RAG、Function Calling、后端工程能力。

五项加分技能——多模态模型、强化学习、MLOps、前端开发、AI 安全。

置信度评分为零点七八，标记为 '待人工审核'。右侧可以看到五条证据来源的具体链接。

这个功能的价值在于，帮助企业快速发现尚未标准化但已经开始招聘的新岗位，而不是等六到十二个月后的行业报告。"

### 段落5：演示案例二 — Java 岗位能力更新（1:30）

**[画面：切换到演化趋势页面，选择 Java 后端工程师]**

**旁白**：

"第二个演示案例——既有岗位的能力动态更新。我们选取最成熟的 Java 后端工程师。

系统通过 role_aliases 将所有 Java 相关的岗位变体合并，然后从 skill_trends 中提取了 2024 年和 2025 年的技能需求数据。

大家可以看到热力图的对比——"

**[画面：2024 vs 2025 技能热度对比]**

**旁白**：

"三个最显著的变化。

第一，Kubernetes 从 2024 年的几乎不出现，到 2025 年热度指数达到七十一，成为仅次于 Docker 的基础设施核心技能。

第二，大模型 API 集成和向量数据库作为全新技能出现在 JD 中——这反映了 AI 能力正在渗透传统的后端岗位。虽然目前热度还不高，但增长趋势非常明显。

第三，SSH、Struts、SVN 等传统技能已经完全消失或极低频率出现。

同时我们也看到，Java、Spring Boot、MySQL、Redis 这四个核心技能的热度始终最高且保持稳定——技术栈在扩展，但基础没有变。

从维度层面看，智能技术能力增幅最大，达到十四个百分点；基础设施能力增长二十二个百分点。这意味着 Java 后端工程师正在从纯工程角色向 '工程加 AI' 的混合角色演进。"

### 段落6：知识图谱可视化（0:45）

**[画面：切换到图谱页面 → Neo4j Browser]**

**旁白**：

"切换到图谱可视化。这是岗位、技能、能力维度之间的关系网络。

蓝色节点是岗位——比如 AI 智能体工程师、Java 后端工程师。绿色节点是具体技能——LangChain、Kubernetes、Spring Boot。橙色节点是能力维度——智能技术能力、基础设施能力、工程研发能力。

连线表示三种关系——实线是必备技能、虚线是加分技能、点线是技能归属维度。

我们也可以直接在 Neo4j Browser 中用 Cypher 查询——比如查找所有与 Java 后端工程师关联的技能节点，以及它们的需求热度变化。"

### 段落7：人岗匹配诊断（0:45）

**[画面：切换到匹配页面，输入一段简历文本]**

**旁白**：

"最后看人岗匹配。我们输入一段候选人简历——比如一个两年 Python 经验的开发者，目标是 Java 后端工程师。

系统首先用同义词词典做技能归一，然后在简历中搜索匹配。结果显示匹配分为——比如四十五分——属于 '重点补齐期'。

左侧显示命中的技能——比如 Git、Linux、MySQL；右侧显示缺失的高权重技能——Spring Boot、微服务、JVM 调优。

每个能力维度有单独的得分，雷达图直观展示优势和短板。

系统还生成了一份十二周的分阶段学习计划——第一到二周补齐基础概念，第三到六周完成可展示项目，第七到十二周岗位化冲刺。

AI 分析是一个可选组件——默认使用规则引擎，配置 DeepSeek API Key 后可以增强分析解释，但 AI 的分析不能覆盖规则引擎的评分结果。"

### 段落8：总结与展望（0:45）

**[画面：总结页，核心亮点列表]**

**旁白**：

"总结一下我们的四项核心创新。

第一，全链路数据溯源——从采集到图谱到匹配，每个结论都可以追溯到原始 JD。

第二，三层幻觉防控——规则引擎约束、图谱事实校验、人工审核标记，确保大模型输出有据可查。

第三，三万四千条岗位别名消歧——解决多源异构数据中岗位名称不一致的根本问题。

第四，四层质量联动闸门——质量评分不是一份独立的报告，而是联动影响图谱构建、趋势统计和匹配可信度。

我们也诚实地说明当前的局限——RAG 检索增强生成的数据已准备，但运行时检索链尚未完成，标记为开发中。趋势预测仅做历史聚合，预测模型待训练。匹配评分的校准方案已文档化，代码实施是近期最高优先级。

比赛后，我们计划在两个月内完成评分校准和双人标注评测体系，六个月内上线 RAG 和趋势预测。

谢谢大家。"
