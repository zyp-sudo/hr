## 1. 项目背景与问题定义

### 1.1 核心痛点

当前招聘领域存在三个突出矛盾：

1. **新岗位识别滞后**：AI 提示工程师、向量数据库架构师等新兴岗位在企业内部从出现到标准化定义通常滞后 6–12 个月，高校专业设置更滞后 2–3 年。
2. **既有岗位能力漂移**：Java 后端工程师从 2020 年的 "SSM + 单体架构" 已演变为 2025 年的 "云原生 + AI 集成 + 向量检索"，但多数岗位 JD 和能力模型未及时更新。
3. **人岗匹配依赖关键词**：现有招聘系统的匹配主要基于简历关键词命中，缺乏技能层级、能力维度和证据链推理。

### 1.2 项目定位

本项目定位为**"多源异构数据驱动的岗位能力图谱与动态演化分析系统"**，服务两个核心场景：

- **企业侧**：发现新兴岗位、更新既有岗位能力要求、提升招聘和人才培养决策效率。
- **求职者侧**：理解目标岗位能力要求、诊断个人能力差距、获得学习路径建议。

---

## 2. 设计理念与建设原则

### 2.1 先闭环，再智能

先保证"数据 → 图谱 → 分析 → 匹配 → 建议"的完整链路能运行。RAG、大模型深度推理等能力后续接入，但不阻塞第一版闭环。

### 2.2 数据必须可解释

每个岗位能力项都带来源、时间、权重、趋势和是否必备字段。系统不只输出结论，还要能说明结论从哪里来。

### 2.3 图谱不是静态图

岗位能力图谱支持动态演化，展示不同时间段内某个岗位的技能需求热度变化，后续扩展趋势预测。

### 2.4 大模型输出必须有约束

大模型生成结果须经过来源回查、图谱事实校验和人工审核标记，避免"能力幻觉"。

### 2.5 匹配不靠关键词

采用"规则 + 词典同义词归一 + 图谱路径 + 能力维度评分"的混合匹配策略。

## 3. 总体技术流程

```text
多源数据采集 (public APIs + CSV imports)
  → 数据清洗与质量评分 (扣分制, 12维度)
  → ETL 统一 Schema (30+字段，全溯源)
  → 岗位能力图谱构建 (节点: 岗位/技能/能力维度; 边: requires/belongs_to/bonus/part_of)
  → 动态演化分析 (月度技能需求热度时序)
  → 人岗匹配诊断 (规则权重 + 同义词归一 + AI辅助分析(可选))
  → 差距解释与学习路径建议 (12周分阶段计划)
```

**匹配算法**（规则引擎）：

```text
1. 加载目标岗位的必备技能列表及权重
2. 对每个技能做同义词展开（skill_aliases.csv）
3. 在简历文本中做归一化匹配（大小写、分隔符、缩略词归一）
4. 总分 = (命中技能权重合计 / 总权重) × 100
5. 按能力维度聚合维度分
6. 生成缺失技能清单、学习建议和分阶段发展计划
7. 可选：DeepSeek API 增强分析（含证据约束和校准 prompt）
```

## 6. 创新性设计

### 6.1 数据溯源全链路（创新点 1）

每条数据从采集到图谱到匹配结论，保留完整溯源链：

```text
source_id → source_type → source_url → collected_at → published_at
  → content_hash → quality_score → quality_flags
  → 岗位能力图谱边（带权重和置信度）
  → 匹配证据（命中技能 + 匹配来源）
```

### 6.2 图谱事实约束的 AI 输出（创新点 2）

设计"规则引擎先约束 → 图谱事实回查 → AI 解释受限"的三层架构：
- **第一层**（已实现）：确定性规则评分，AI 不可覆盖
- **第二层**（已实现）：图谱事实注入 AI context，限制编造
- **第三层**（⚠️ 开发中）：RAG 检索增强，带 `sourceIds` 的生成约束

### 6.3 岗位实体消歧与别名合并（创新点 3）

34,094 行消歧证据，将 "Java开发、Java工程师、JAVA后台、后端开发" 等异构 JD 标题映射到规范岗位 ID，解决多源数据中岗位名称不一致的核心问题。

### 6.4 数据质量联动闸门（创新点 4）

数据质量不仅单独评分，还联动影响下游应用：
- C/D 级记录不进入核心指标口径
- 无技能命中记录不生成 requires 图谱边
- 重复 content_hash 只保留一份用于趋势统计
- 低质量岗位降低匹配推荐可信度
