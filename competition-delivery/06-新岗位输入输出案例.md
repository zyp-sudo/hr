> **项目编号**：XH-202621
> **编写日期**：2026-07-17
> **对应评分维度**：创新性（25分）、体验（15分）、实用价值（30分）

---

## 1. 案例概述

本文件展示系统对**新兴岗位**的发现与定义能力。案例选取 **"AI 智能体工程师"（AI Agent Engineer）**，这是一个典型的 2024–2025 年兴起、尚未标准化、但在多个企业官网和行业报告中高频出现的新兴岗位。

**案例数据来源**：
- 企业 JD 采集数据（腾讯/美团/华为招聘）
- `data/discoveries.csv` 中的新岗位发现样例
- `data/competition/discoveries.json` 中的结构化发现结果
- 规则引擎 + DeepSeek（dry-run）抽取结果

---

## 2. 输入：多源招聘数据

### 2.1 输入数据概况

系统接收来自多个渠道的岗位 JD，其中包含传统岗位分类中无法归类的职位名称。

**示例原始 JD 标题**（经过去隐私处理）：

| 原始标题 | 来源 | 采集时间 |
|----------|------|----------|
| "AI Agent 开发工程师" | 腾讯招聘 | 2025-06 |
| "智能体平台后端研发" | 美团招聘 | 2025-05 |
| "大模型应用开发工程师（Agent方向）" | 华为招聘 | 2025-07 |
| "LLM Application Engineer - Agentic Workflow" | 腾讯招聘 | 2025-07 |
| "AI 应用开发工程师（智能体）" | 美团招聘 | 2025-06 |

### 2.2 输入特征分析

这些 JD 标题的共同特征：

1. **岗位名称未标准化**：同一岗位有 5+ 种不同写法
2. **技能组合新颖**：既需要传统后端工程能力，又需要大模型/Agent 框架知识
3. **没有成熟的分类对应**：不属于传统的"AI算法工程师"（偏模型训练），也不属于"后端工程师"（偏CRUD）
4. **出现频率增长**：2025 年上半年在多个企业官网同时出现

## 3. 处理流程

### 3.1 系统处理步骤

```text
步骤1: 技能抽取与聚类
  输入: 5条原始JD的responsibility + requirement文本
  处理:
    - 规则引擎抽取技能关键词
    - 同义词归一：Agent/智能体 → 统一为 "AI Agent"
    - 技能→能力维度映射
  输出: 高频技能列表 + 维度分布

步骤2: 岗位实体消歧
  输入: 5种不同岗位名
  处理:
    - role_aliases.csv 匹配现有别名
    - 未命中 → 标记为 "候选新岗位"
    - 名称相似度聚类：AI Agent 工程师 / LLM 应用工程师 → 同簇
  输出: 候选新岗位簇

步骤3: 岗位定义生成
  输入: 聚类后的JD集合 + 高频技能 + 能力维度
  处理:
    - 提取核心职责（出现频次 ≥ 60% 的职责描述）
    - 提取必备技能（出现频次 ≥ 60% 的技能）
    - 提取加分技能（出现频次 30%-60% 的技能）
    - 生成典型应用场景
  输出: 新岗位定义卡片

步骤4: 置信度评估
  输入: 岗位定义 + 来源JD数量 + 来源多样性 + 时间跨度
  处理:
    - 来源数 ≥ 2 → 置信度 +0.2
    - 企业类型 ≥ 2 → 置信度 +0.15
    - 时间跨度 ≥ 3个月 → 置信度 +0.1
    - 技能维度覆盖 ≥ 3 → 置信度 +0.1
  输出: 置信度评分 + 人工审核标记
```

### 3.2 关键代码路径

```
Python: GET /api/competition/discoveries → competition_core.list_discoveries()
  → 读取 data/discoveries.csv
  → 返回新岗位发现样例

Python: python scripts/build_knowledge_graph.py
  → 分析 normalized_category 的分布
  → 标记 category="其他" 的高频岗位名
  → 写入 role_aliases.csv（新别名→新规范ID）
```

### 4.2 输出解读

**置信度 0.78 的含义**：
- 来源数 3 个企业（腾讯/美团/华为）→ 多样性较好
- JD 数量 5 条 → 样本量偏小，置信度适度扣减
- 时间跨度 3 个月（2025-05 至 2025-07）→ 持续性初步验证
- 岗位名标准化程度低（5种写法）→ 说明行业尚未统一命名，符合"新岗位"特征

**"待人工审核"标记的原因**：
- JD 样本量较��（5条）未达到自动确认阈值（≥10条）
- 与"AI算法工程师"的边界需要领域专家判断
- 技能要求列表可能需要进一步精简

## 7. 案例价值说明

### 7.1 对应比赛评分维度

| 评分维度 | 覆盖内容 |
|----------|----------|
| 创新性（25分）| 从非结构化多源JD中自动聚类发现新岗位、岗位定义生成、与传统岗位的差异分析 |
| 体验（15分）| 结构化的新岗位定义卡片、可追溯的证据来源、可视化图谱关系 |
| 实用价值（30分）| 解决企业"新兴岗位识别滞后"的实际痛点、为高校专业设置提供数据依据 |

### 7.2 当前局限性（诚实声明）

| 局限 | 说明 |
|------|------|
| 样本量有限 | 当前新岗位发现仅基于少量JD样本，主要依赖 `discoveries.csv` 中的预定义样例 |
| 自动化程度 | 新岗位聚类和定义生成的完整自动化链路尚未完全实现，部分依赖人工整理的样例数据 |
| 大模型参与 | 岗位定义生成在 dry-run 模式下使用规则模板，配置 API Key 后可切换 DeepSeek 生成 |
| 动态更新 | 新岗位发现尚未实现持续监控和自动更新，当前为按需触发的快照模式 |
| 置信度校准 | 置信度评分公式为初步设计，未经过大规模标注数据的校准验证 |
