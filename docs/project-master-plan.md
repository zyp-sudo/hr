# XH-202621 项目总设计文档

## 1. 项目定位

本项目不是单纯的岗位展示系统，也不是只做知识图谱可视化。它的目标是构建一个“多源异构数据驱动的岗位能力图谱与动态演化分析系统”。

系统要服务两个核心场景：

- 企业侧：发现新兴岗位、更新既有岗位能力要求、提升招聘和人才培养决策效率。
- 求职者侧：理解目标岗位能力要求、诊断个人能力差距、获得学习路径建议。

第一阶段先做可运行、可演示、可替换数据的比赛原型；第二阶段再逐步接入真实 JD 数据、简历解析、图数据库、向量检索和大模型能力。

## 2. 建设原则

### 2.1 先闭环，再智能

先保证“数据 -> 图谱 -> 分析 -> 匹配 -> 建议”的完整链路能运行。大模型、OCR、Neo4j、向量库等能力后续接入，但不应该阻塞第一版闭环。

### 2.2 数据必须可解释

每个岗位能力项都应尽量带来源、时间、权重、趋势和是否必备等字段。系统不只输出结论，还要能说明结论从哪里来。

### 2.3 匹配不能只靠关键词

第一版先实现技能同义词归一和权重评分，例如 `K8s -> Kubernetes`、`Vector Search -> 向量检索`。后续升级为“规则 + 词典 + 向量相似度 + 图谱路径 + 大模型解释”的混合匹配。

### 2.4 图谱不是静态图

岗位能力图谱必须支持动态演化。至少要能展示不同时间段内某个岗位的技能需求热度变化，后续再做趋势预测。

### 2.5 大模型输出必须有约束

大模型用于实体抽取、关系推理、岗位定义生成、学习路径建议，但生成结果必须经过来源回查、图谱事实校验和人工审核标记，避免“能力幻觉”。

## 3. 总体流程

```text
多源数据采集
  -> 数据清洗与质量评分
  -> JD/简历/报告结构化解析
  -> 岗位、技能、能力维度抽取
  -> 实体消歧和技能标准化
  -> 岗位能力图谱构建
  -> 动态演化分析
  -> 人岗匹配诊断
  -> 差距解释和学习路径建议
```

## 4. 功能总览

### 4.1 数据管理模块

目标：让系统有可替换、可审计的数据基础。

第一版功能：

- 使用 `data/*.csv` 管理岗位、技能、同义词、演化趋势、数据源、简历样本。
- 前端提供“样本数据”页面，展示当前读入的数据。
- 后端提供 `GET /api/samples` 用于验证数据来源。

后续功能：

- 支持上传 JD、简历、行业报告。
- 支持数据源、时间戳、质量分、重复度和可信度管理。
- 支持至少 100 条 JD 测试数据，最终扩展到 1000+ JD。

### 4.2 岗位发现与定义模块

目标：识别新兴岗位并生成岗位定义。

第一版功能：

- 用 `data/discoveries.csv` 保存新兴岗位样本。
- 输出岗位名称、置信度、核心职责、必备技能、加分技能、证据来源。

后续功能：

- 基于 JD 频次增长、企业官网新增岗位、行业报告高频词发现候选岗位。
- 使用大模型生成岗位定义。
- 用图谱事实和数据来源校验生成结果。

### 4.3 岗位能力图谱模块

目标：表达岗位、技能、能力维度之间的结构关系。

第一版功能：

- 根据 `jobs.csv` 和 `job_skills.csv` 构建图谱节点和边。
- 节点类型包括岗位、技能、能力维度。
- 边类型包括 `requires`、`bonus`、`belongs_to`。

后续功能：

- 接入 Neo4j。
- 支持技能层级、同义关系、前置技能、岗位相似关系。
- 支持图谱版本管理和时间属性。

### 4.4 动态演化分析模块

目标：展示岗位能力需求随时间变化。

第一版功能：

- 使用 `evolution.csv` 展示岗位技能热度时间序列。
- 支持按岗位查询演化数据。

后续功能：

- 根据真实 JD 的发布日期、来源和技能频次计算趋势。
- 支持 2024 vs 2025 对比。
- 支持未来 3-6 个月技能需求预测。

### 4.5 人岗匹配诊断模块

目标：分析候选人与目标岗位之间的能力差距。

第一版功能：

- 输入简历文本。
- 技能同义词归一。
- 按岗位技能权重计算匹配分。
- 输出命中技能、缺失技能、维度分数、学习建议。

后续功能：

- 支持 PDF/Word 简历解析。
- 支持教育经历、项目经历、年限、证书、行业经验等多维匹配。
- 引入向量相似度和图谱路径距离。
- 以证据链方式解释匹配结果。

### 4.6 数据质量与幻觉防控模块

目标：提升图谱构建的可信度。

第一版功能：

- 使用 `data_sources.csv` 保存数据源类型、样本数、质量分、时效性和说明。
- 在能力项中保留来源字段。

后续功能：

- 重复 JD 聚类。
- 来源交叉验证。
- 时间衰减评分。
- 无来源能力项标记为待审核。
- 大模型生成内容必须绑定 sourceIds。

## 5. 当前技术路线

### 5.1 第一版技术栈

- 前端：Python 标准库 HTTP 服务。
- 后端：Java 标准库 HTTP Server。
- 数据：CSV 文件。
- 图谱展示：前端 SVG 简易图。
- 匹配算法：技能词典 + 同义词归一 + 权重评分。

选择原因：不先引入复杂依赖，保证本地快速运行，先把比赛闭环搭起来。

### 5.2 目标技术栈

- 数据采集：Scrapy + Playwright。Scrapy 处理静态页面，Playwright 处理 JS 动态渲染页面，配合代理池、限速、重试和反爬策略。
- 数据存储：MySQL + Elasticsearch。MySQL 存储结构化岗位、技能、来源和质量评分，Elasticsearch 支持全文检索和聚合分析。
- NLP 处理：HanLP / LAC + DeepSeek API。HanLP/LAC 做中文分词、词性和 NER 基础处理，DeepSeek 做复杂语义理解、实体消歧和关系抽取。
- 知识图谱：Neo4j + py2neo。Neo4j 存储岗位、技能、能力维度和时序关系，py2neo 提供 Python 写入和查询接口。
- 图谱可视化：AntV G6 / ECharts Graph。G6 支持力导向布局、节点聚类和交互探索，ECharts Graph 用于轻量图展示。
- RAG 框架：LangChain + ChromaDB + DeepSeek API。LangChain 编排 DeepSeek 调用链，ChromaDB 做向量存储，实现检索增强生成。
- 后端框架：FastAPI / Flask。FastAPI 性能优异，自带 OpenAPI 文档，Flask 可作为更轻量的替代。
- 前端框架：Vue 3 + Vite + Pinia。Vue 生态成熟，Vite 构建快，Pinia 状态管理简洁。
- 数据分析：Pandas + NetworkX。Pandas 做数据清洗和统计分析，NetworkX 做中心性、社区发现、相似岗位聚类和路径分析。
- 简历解析：PaddleOCR / Tesseract + PDF/Word 本地解析 + 自定义 NER。本地 OCR 处理图片和扫描版 PDF 简历，PDF/Word 本地解析处理文本型简历，自定义 NER 提取技能、项目、年限、教育、证书等结构化字段。

当前代码仍保留 Python 前端、Java 后端和 CSV/JSON 文件层，目的是保证比赛原型可运行。目标技术栈作为后续生产化升级路线，优先承接当前已经生成的 `data/etl/*.csv` 和 `data/kg/*.csv` 产物。

## 6. 数据文件设计

当前数据层位于 `data/`：

- `jobs.csv`：岗位基础信息。
- `job_skills.csv`：岗位技能、维度、级别、权重、是否必备、来源、趋势。
- `skill_aliases.csv`：技能同义词归一。
- `evolution.csv`：岗位技能需求时间序列。
- `data_sources.csv`：数据源质量评分。
- `resume_samples.csv`：简历文本样本。
- `discoveries.csv`：新兴岗位发现样本。
- `collected_jobs.csv`：真实采集岗位总表，包含中国和海外来源。
- `collected_job_skills.csv`：从真实岗位职责和要求中抽取的技能命中记录。
- `collected_sources.csv`：真实数据来源记录。
- `china_jobs.csv`：中国岗位分表。
- `foreign_jobs.csv`：海外岗位分表。

后续真实数据进入系统前，应先映射到这些结构，再考虑数据库化。

## 7. API 总览

- `GET /api/health`：健康检查。
- `GET /api/jobs`：岗位列表。
- `GET /api/graph`：岗位能力图谱。
- `GET /api/evolution?jobId=...`：岗位能力动态演化。
- `GET /api/data-quality`：数据源质量评估。
- `GET /api/samples`：当前样本数据。
- `POST /api/match`：人岗匹配诊断。
- `POST /api/discover`：新兴岗位发现样例。
- `GET /api/real-jobs`：真实中国岗位数据、技能统计和城市统计。

## 8. 里程碑

### M1：文件数据驱动原型

状态：已完成初版。

- 后端读取 CSV。
- 前端展示样本数据。
- 匹配支持权重和同义词。
- 图谱和演化可展示。

### M2：真实 JD 数据导入

目标：

- 准备至少 100 条岗位 JD。
- 建立 JD 原文、来源、发布时间、岗位类型、技能抽取结果。
- 增加数据导入和样本查看页面。

当前进展：

- 已接入腾讯招聘公开岗位接口。
- 已实现多源采集主入口 `scripts/crawl_jobs_100k.py`。
- 已保留腾讯招聘适配器 `scripts/crawl_tencent_jobs.py`，由多源主入口统一调度。
- 重新采集后会写入 `data/collected_*.csv`、`data/china_jobs.csv`、`data/foreign_jobs.csv` 并进入 ETL。

### M3：简历解析能力

目标：

- 支持 PDF/Word 简历上传。
- 提取技能、项目、年限、教育、证书等字段。
- 建立简历提取准确率评估样本。

### M4：图谱与 RAG

目标：

- 接入 Neo4j 或等价图存储。
- 接入向量检索。
- 大模型生成岗位定义和学习路径。
- 生成内容带来源校验。

### M5：比赛交付强化

目标：

- 测试数据 >= 100 条 JD。
- 单元测试覆盖率目标 >= 60%。
- 形成设计文档、PPT、演示脚本、部署说明和演示视频素材。

## 9. 开发纪律

后续每次新增功能前，先确认它属于本文档中的哪个模块和里程碑。

如果功能不属于当前里程碑，先记录到后续路线，不直接扩散实现范围。

任何新增数据字段，都要同步更新：

- 数据文件说明。
- 后端读取逻辑。
- API 返回结构。
- 前端展示。
- README 或相关文档。

任何模型或算法输出，都要尽量保留：

- 输入数据。
- 命中证据。
- 数据来源。
- 置信度或分数。
- 人工审核状态。
